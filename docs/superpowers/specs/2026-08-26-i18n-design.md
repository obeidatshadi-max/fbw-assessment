# Prompt 1 — i18n (EN/AR/FR) design — APPROVED, not yet implemented

Status: user approved this design 2026-08-26. Next step when resuming:
implement directly (bounded refactor, TDD, no separate plan doc needed).

## Decisions locked in
- Default language on load: **English**.
- Rollout: **all three languages (en/ar/fr) in one pass**, not Arabic-first.
- Arabic font: **Noto Kufi Arabic** (Google Fonts) + system RTL fallback.
  English/French keep Fraunces + IBM Plex Sans.
- Persist language choice in `localStorage` key `fbw-lang`.

## Design
- `src/i18n/translations.js` — single object keyed `en`/`ar`/`fr`, covering
  every UI string (headings, buttons, chip labels, nav, disclaimer) **and**
  the content banks (`SCENARIOS`, `ORG_ITEMS`, `DIM` strength/watch/develop)
  reshaped so each string is `{en, ar, fr}` instead of a bare string.
- `src/i18n/LanguageContext.jsx` — React context holding current lang +
  setter, persisted to `localStorage`.
- Language switcher (EN / AR / FR toggle) added to `Header.jsx`.
- `dir="rtl"` + a `[dir="rtl"]` CSS block in `global.css` mirroring nav,
  progress bar, profile left-borders, bars. English/French stay LTR.
- Every component (`IntroScreen`, `ScenarioScreen`, `OrgScreen`,
  `ReportScreen`, `AuthPanel`, `Navbar`) reads strings via a `t()` helper
  off context instead of hardcoded English — existing component tests get
  a language-switch test added.
- `scoring.js` / `answers.js` untouched — language is a pure rendering
  concern, zero regression risk to the scoring math.
- Any Arabic/French line the implementer is genuinely unsure of: flag in
  the commit message + a `// REVIEW:` code comment, do not guess silently
  — Shadi is the domain/language owner and corrects drafts.
